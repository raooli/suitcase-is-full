## 2. 阻塞-1 修复记档：11 张灰底假透明（2026-10-17）

### 2.1 现象与根因

| 项 | 读数 |
| --- | --- |
| 涉事 | `prop_02_A~D`（B1，`58c5b68` 覆盖替换）、`prop_04_A~D`、`prop_jacket`、`prop_pouch`、`prop_scarf`（B2，`e5b722e`）共 **11 张** |
| 症状 | 四角 alpha=255、不透明覆盖率 **100%**、bbox 四边距 0、外缘环带全不透明——合成到页面奶油底上是**灰色矩形块** |
| 连带伤害 | 编辑器自动裁剪失效：`.meta` 的 `trimX/trimY/width/height` 全为 0/全画布（灰底把透明边距吃掉了） |
| 根因 | 两个批次提交的图带**均匀 `#E5E5E5` 灰底**（环带 100% 单一色）。B1 是回归：`cebf419` 旧版四角 alpha=0、覆盖 32% 合格，`58c5b68` 覆盖替换后未复检 |
| 为什么不能颜色键控 | 灰底与 C 家族织物主色 `#E5E5E5` **同色**，键控会把帆布袋/外套主体一起吃掉 |

### 2.2 修复方法与验证（描边抠图，非重新出图）

SVG 源只有 3 张（不含这 11 张），走像素级抠图（脚本存档于 `/tmp/m43-cutout.mjs`，手法已记入 MEMORY.md）：

1. **边缘洪水填充**：从画布边缘把与底色欧氏距 ≤ 8 的连通像素置透明（底色 100% 均匀；容差 8 远低于物体奶油填充的 16.3 与抗锯齿混色的 ~37，不会误吃）
2. **光晕 alpha 恢复（unflatten）**：对邻接全透明的实色像素按 `p = a·fg + (1-a)·bg` 反解 alpha 与本色，fg 取邻域最远非候选实色；**共线性保护**——像素必须落在 bg→fg 线段上才处理，实色边缘因描边缺口暴露时共线失败被跳过，不会被打出软洞
3. **零 RGB 置底**：全透明像素 RGB 归零（体积更小、避免预乘歧义）

**验证**（`npm run check:art` + `art/review-pixels.py` 双轨）：

| --- | --- | --- |

| `.meta` trim | 全 0（裁剪失效） | 重建生效（如 `prop_02_A` trimX=34/trimY=19，与透明边距吻合） |

## 7. 出图规格速查（转交美术时直接贴这段）

```
画布    = 包围盒列数 × 96（宽） × 包围盒行数 × 96（高）
单格    = 96 物理像素（逻辑 cellSize 48px 的 @2x）
朝向    = 该 itemType 的 cells 在 rotation=0 时的朝向（不能凭物件常识决定）
格式    = PNG-24 透明底（RGBA），禁止白/灰底假透明
命名    = sprites/props/<itemType>.png，严格等于 itemType，不加语义后缀
出血    = ≤10%，且不得遮挡邻格判定提示；物体不得出画布边缘
单图上限 = 512×512
四朝向  = 不出图，由引擎节点旋转实现（1 张而非 4 张）
家族    = 对照 docs/07-AI-Prompts.md 5.6「家族」列 + 5.2 逐关规则（≥3 家族/关、同家族 ≤2 件、≥1 重色件）
```

**形状与朝向以 `npm run art:missing` 的输出为准**——它会列出每件物品的 `itemType / 名称 / 形状 / 期望画布 / 出现关卡`。
