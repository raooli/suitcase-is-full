## 3. 目录约定（已重构）

| 目录 | 内容 | 是否进包 |
| --- | --- | --- |
| `art/art-source/props/` | **手绘件**的 SVG 矢量源，可编辑，允许语义后缀（`prop_01_A_phone.svg`）。现有 3 件 | ❌ 不进包（在 `assets/` 之外） |
| `art/art-source/props/ai/` | **AI 生成件**的「源」= 逐件提示词 + 生成参数 + 后处理命令（`<itemType>.prompt.md`） | ❌ 不进包 |
| `art/previews/props/` | 生成原图留档（白底未抠，长边 512 JPEG，`<itemType>_reference.jpg`）+ 早期 2 张 PNG 参考图 | ❌ 不进包 |
| `assets/resources/sprites/props/` | **Cocos 实际使用的透明 PNG**，文件名**严格 = `itemType`** | ✅ 进包 |

> 为什么 sprites 必须在 `assets/resources/` 下：Cocos 只有 `resources/` 目录支持 `resources.load()` 动态加载。物品按 `itemType` 运行时加载，不做 63 项手工映射。

**AI 件为什么不产 SVG**：图像模型只出位图（实测连 alpha 通道都不给）。把成品再矢量化，得到的是对「16 色量化结果」的二次近似——边缘失真、半透明光晕丢失，且体积不减。这种假源比无源更危险（后人照它改图，误差会累积且不可查）。所以 AI 件的源定义为**能重新生成它的最小输入**，落在 `ai/*.prompt.md`；公共 Style Block 仍在 `docs/07` §5.1，不复制以免两处漂移。

**原图为什么只存 512 缩略**：原图 1024×1536 级、单张 1–2 MB（本批 8 张共 10 MB），63 张齐会到 ~80 MB，git 吃不住。原图只用于人工比对与 image reference，模型侧还会再降采样，512 长边够用（重出图靠提示词重新生成，不是拿旧图放大）。本批 8 张缩略合计 266 KB。详见 `art/art-source/props/ai/README.md`。

### 5.1 M4-6 异形件剪影修复记档（2026-10-19）

**现象**：M4-5a 真图接线后真机试玩，L2 帆布袋（cells `XX/X.`）等 14 张异形件图是填满包围盒的矩形——视觉侵入非占格，与该格实际可放邻居物品矛盾；拖拽 ghost 是逐格色块（L 形），与托盘/盘上真图（矩形）形状割裂。

**根因**：美术管线只传播包围盒（提示词要求「fill the canvas edge to edge」、check-art 只验画布尺寸、引擎整幅映射到包围盒节点）；物品占格实为多联骨牌（`cells`），契约从未要求剪影匹配足迹。

**最终修复（用户复核后裁决：重绘贴合形状，不硬裁；ghost 保持逐格色块）**：
- 首轮曾对 14 张直接烘焙遮罩（挖非占格），用户看图否决——主体被切残（发饰缺角等），要求「重新设计物品去匹配形状，而不是硬裁」。14 张 PNG 回退重做。
- 最终路线：按 levels.json 的 `cells` 生成**逐格置物式提示词**（明确哪个格放什么、哪个格必须空），AI 重绘 14 件使物品本身呈多联骨牌形；`fit` 的足迹遮罩作为**兜底**（AI 少量越界时清零，不依赖它切主体）。
- 提示词迭代经验：① 单物体跨多格（笔记本 / 相机带 / 外套 / 长裙）必须写「ONE single …」「单一连续物体，禁止分段/平铺」，否则模型逐格重复成多个；② L 形足迹（长裙 `..X/..X/XXX`）改用「折叠平放成 L 形」语义；③ 近白填充（如白布）会被抠底吃掉，须改明确彩色 + 描边。
- `tools/art-batch-proc.mjs`：`fit` 合版后自动应用足迹遮罩（`--no-mask` 可跳过）；`mask` 子命令保留作追溯兜底。
- `tools/check-art.ts` 剪影门禁：非占格内部（内缩 2px）有不透明像素 = 阻塞；占格覆盖率 <2% = 警告。
- 附带修复（M4-6 同批）：`ItemView.createArtNode` 旋转感知映射——修复前可旋转物品旋转 90° 后真图两轴缩放不同被拉扁（实测 2×4 薄外套 0.59 vs 2.38）；新增 core 纯函数 `rotatedCenterOffset` + 单测（与 `rotateBy` 七形×四向交叉验证）。
- 验证：`check:art` 25/25 剪影合规；L2 托盘帆布袋呈「包身 + 右上肩带」L 形；L5 选件旋转 90° 后 `artEuler=-90`、artSize 不变（不拉伸），零 Console 错误。

## 7. 出图规格速查（转交美术时直接贴这段）

```
画布    = 包围盒列数 × 96（宽） × 包围盒行数 × 96（高）
单格    = 96 物理像素（逻辑 cellSize 48px 的 @2x）
朝向    = 该 itemType 的 cells 在 rotation=0 时的朝向（不能凭物件常识决定）
剪影    = **cells 足迹**：占格区域（布局 ASCII 的 X）画出主体，非占格区域（.）完全透明；
          异形件（L/T/S…）禁画满包围盒——出图后由 art-batch-proc fit 自动挖除，check:art 门禁验收
格式    = PNG-24 透明底（RGBA），禁止白/灰底假透明
命名    = sprites/props/<itemType>.png，严格等于 itemType，不加语义后缀
出血    = 只允许进入占格区域；不得遮挡邻格判定提示；物体不得出画布边缘
单图上限 = 512×512
四朝向  = 不出图，由引擎节点旋转实现（1 张而非 4 张）
家族    = 对照 docs/07-AI-Prompts.md 5.6「家族」列 + 5.2 逐关规则（≥3 家族/关、同家族 ≤2 件、≥1 重色件）
```

**形状、朝向与足迹布局以 `npm run art:missing` 的输出为准**——它会列出每件物品的 `itemType / 名称 / 形状 / cells 布局（X=占格） / 期望画布 / 出现关卡`。

## 8. 校验命令

| 命令 | 作用 |
| --- | --- |
| `npm run check:art` | 报告：覆盖率、缺失、尺寸/朝向不符、**透明底**、**剪影 = cells 足迹**、孤儿文件 |
| `npm run art:missing` | 输出缺失清单（含 cells 布局 ASCII，可直接交给美术照形状画） |
| `npm run check:art:strict` | 门禁：63 张齐全且全部符合规格（含透明底与剪影）才退出 0（M4 收尾用） |
| `python3 art/review-pixels.py` | 像素级复审（stdlib）：逐张输出主色聚类/最近家族@距离/覆盖率/fringe/剪影核查——批次评审与家族合规核算用 |
| `node tools/art-batch-proc.mjs mask <itemType> [--dry-run]` | 对已交付 PNG 补烘焙足迹遮罩（M4-6 追溯修复用；fit 出图时自动执行） |

> 收到新图后放进 `assets/resources/sprites/props/`（文件名 = itemType），跑一次 `npm run check:art` 即知是否合格——**尺寸、命名、透明底全部自动核查，不用肉眼量**。
