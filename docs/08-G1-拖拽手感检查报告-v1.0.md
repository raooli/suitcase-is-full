### 为什么撤销不给临时手势（与旋转不对称，这是有意的）

M1-8 给旋转补了「选中后再次点击 = 旋转」的临时入口，看起来撤销也该照办，但两者**性质不同**：

1. **规格依据不同**。旋转有明文授权：UI Spec 5.2「旋转采用固定 90°，可在已选中时点击按钮」+ 交互表「Selected → 点击旋转」——旋转是**作用于被选中对象**的直接操作，点它自己即可。撤销没有对应手势，UI Spec 5.2 把它明确定在**底部工具栏**（「底部：撤回、旋转、提示」），而工具栏是 M2-2 才建。
2. **可逆性不同**。旋转四次回到初态、不破坏任何已提交状态；撤销**销毁一次已提交的放置且 MVP 没有重做**（core `History` 只有 `canUndo`，无 redo）。用临时手势承载一个不可恢复的破坏性操作，误触没有救济。
3. **会撞已定义的手势**。可选的空白区手势都被占用了：交互表「Selected → 点击棋盘空白或托盘空白 → 取消高亮，回到 Idle」。双击/长按棋盘空白做撤销，会与「点空白取消选中」抢同一次触摸——症状是**想取消高亮却撤掉了一步**。
4. **会制造第二套肌肉记忆**。M2-2 的工具栏按钮一定会替换掉临时入口，玩家刚学会的手势又要改。

**结论**：撤销的玩家入口等 M2-2 的工具栏，与规格一致。M1 阶段如需端到端验「撤销无残影」，走无头夹具（`tools/preview-check.mjs`）而不是给玩家造入口——但 `undo-applied` 走的是和 `placement-committed` / `item-returned` **完全相同**的 `refreshAll → ItemLayer 全量重绘` 路径（该路径已被四拖通关 + 13 连压力用例覆盖），残影风险因此不是新增路径风险，M2-1 加载多关后连放/撤销一起补验即可。

## G1-1 手指遮挡 —— ✅ 通过（M1-9 实现）

**判据**：UI Spec 6 节「长按并拖动物品 → **物品提升、浅阴影、跟手**」；触屏设计「拖动物品时应采用『**手指不遮挡目标格**』的视觉偏移策略，具体偏移按设备和试玩结果调整」；8 节「拖拽抬起：约 80–120ms，略微放大或加投影」。

**V1.0 现状（已修）**：`PreviewLayer` 的 ghost 曾按手指锚点原样绘制，无上浮 / 无放大 / 无阴影 → 真实手指按下时 ghost 就在指尖正下方，被手完全挡住。

**M1-9 实现**（三个可调常量全在 `core/config.ts`）：

| 常量 | 值 | 依据 |
| --- | --- | --- |
| `UI_DRAG_LIFT_PX` | 24 | ≈ 手指半宽量级；UI Spec 9 节已把该距离列为试玩待定项 |
| `UI_DRAG_LIFT_SCALE` | 1.05 | 「略微放大」——再大就会让玩家误判物品实际占几格 |
| `UI_DRAG_SHADOW_OFFSET_PX` / `UI_DRAG_SHADOW_ALPHA` | 3 / 0.18 | UI Spec 4.1「右下短而淡的结构阴影；禁止长投影、外发光」 |

几何算式提成纯函数 `core/geometry/lift.ts`（`centerOf` / `liftAndScale` / `offsetRects`），配 12 条单测钉死四条不变量：恒等、缩放不改包围盒中心、上浮只改 y、格缝按倍率同比例变化（缩放后仍不重叠）。

**实测读数（无头预览 390×844，`--drag` 第 5 段截 touchEnd 前的 ghost 中途态）**：

```
[PreviewLayer] ghost L01_A@(1,1) rot=0 → ok lift=+24 scale=1.05 nodePos=(0,68) t=12669
```

像素扫描核对（纯 stdlib PNG 解码，扫描线找色块；截图 780×1688 即 2× DPR，下表已折算回设计单位）：

| 量 | 实测 | 期望 | 结论 |
| --- | --- | --- | --- |
| ghost 整体中心 x | 251.75 | col1+col2 包围盒中心 = 138+114 = **252** | ✅ 横向未漂 |
| ghost 整体中心 y | 329.75 | row1 中心 354 − 上浮 24 = **330** | ✅ 上浮量精确 |
| ghost 宽度 | 227 | (2×114 − 2×6.84) × 1.05 = 225.0，+2px 描边 = **227** | ✅ 等比放大未散开 |
| ghost 高度 | 107 | (114 − 13.68) × 1.05 + 2 = **107.3** | ✅ 单格同比 |
| 底部阴影带 | `rgb(231,226,223)` ×626 px、`rgb(231,219,199)` ×625 px | 棕 `#7A5C4F` 18% 叠白 = **(231,226,223)** | ✅ 右下短而淡 |

**阴影的负向对照**（单个像素值可能混进棋盘格线，所以关掉重拍一次同点位比对）：

| ghost 外扩 6px 带的暗像素数 | 阴影开（α=0.18） | 阴影关（α=0） |
| --- | --- | --- |
| 正下方带 | 626 + 625 | 6 |
| 正右方带 | 352 + 126 | 172（背景级） |
| 正上方带 / 正左方带 | 6 / 145（背景级） | 6 / 145（背景级） |

→ 暗像素只出现在**下方与右方**、关掉即消失，与 UI Spec 4.1「右下短而淡」一致；上方/左方两侧开关前后完全一致，说明没有误加反向投影。

**硬约束（三条，全部守住）**：

1. **只改画法，不改判定**——落点仍由手指位置经 `snapToGrid` 算出，`preview.anchor` 一个字没动 → G1-2 复验通过（见下）；
2. **不挪节点**——`nodePos=(0,68)` 全程不变，上浮画在 Graphics 的矩形上（M1-7 踩过：位移 tween 不归位会留下 8px 持久偏移）；
3. 缩放锚点取**整体包围盒中心**，取单格中心会让 1×3 物品散成三块。

**G1-2 复验（防这次改动破功）**：四拖通关，四件物品「最后一次报 `→ ok` 的格」与「实际落格」逐一对上，零漂移：

```
ghost L01_A@(1,1) → ok      放入 L01_A → (1,1) ✅
ghost L01_B@(1,0) → ok      放入 L01_B → (1,0) ✅
ghost L01_C@(2,1) → ok      放入 L01_C → (2,1) ✅
ghost L01_D@(0,0) → ok      放入 L01_D → (0,0) ✅
```

（无头夹具 `--grep 放入` 实跑读数，四拖一次铺满 3×3 并触发通关；`ghost` 报格与 `放入` 落格四四对上。）

非法态（红虚线）同样抬起 —— 拖拽途中 `ghost L01_A@(3,0) rot=0 → out-of-bounds lift=+24 scale=1.05`，与合法态共用同一条 `liftAndScale`，不会出现"合法抬起、非法贴地"的割裂。

**流水线**：`npm run check` **212/212**（含新增 lift 单测 12 条 + `typecheck:view`）；`preview:game` 零 Console 错误。

### V1.2 校准记录（2026-10-17，M3-1 真机）

上面的 24px 是**设计单位初值**，V1.1 已声明待真机校准（G1-D1）。真机试玩反馈：「手指拖动移动到方格上时位移有点大，总感觉没放到正确的方格上」。

| 量 | 修复前实测 | 修复后实测 | 期望 |
| --- | --- | --- | --- |
| ghost 中心（页面 x） | 251.8 | 251.8 | 落点格 (1,1) 包围盒中心 252 |
| ghost 中心（页面 y） | **329.8** | **353.8** | 同上 354 |
| ghost 尺寸（页面） | 225.5×106.5 | 225.5×106.5 | 不变 |

**根因**：上浮只改画法不改判定——ghost 画在落点格上方 24，松手落手指正下方的格。玩家按 ghost 对格 → 落点系统偏下一格（3×3 偏 0.21 格；6×6 偏 0.42 格，用户实际玩到的正是这种偏差）。**处置**：`UI_DRAG_LIFT_PX` 24 → 0（只改 `config.ts` 数值，机制与单测不动），复测误差 0.2px。

**为什么不再补偿判定而是去掉上浮**：把锚点改成"手指 +24 上浮"也能让 ghost 与落点重合，但盘上物品起拖锚点必须等于物品原位（M2-11 复审：改了 ghost 会在按下点靠近格上沿时跳一整格），两条约束不可兼得；而去上浮后本作内容（最小 1×2、无 1 格物品）使遮挡担忧本就不成立。若后续试玩仍报遮挡，走「双视觉拆分」（落点格描边画在落点 + 物品形悬浮指上），**不要**把上浮调回非 0。

## G1-3 旋转手感 —— ✅ 通过

**判据**：「旋转后预览即时更新；`rotate-blocked` 抖动反馈清晰」。

| 子项 | 读数 |
| --- | --- |
| 托盘物品旋转后预览更新 | 点 0 号槽两次 → 缩略图 `60×30`（横）→ `30×60`（竖），且高亮 `selected`。日志：`L01_A@76px(selected) 缩略30×60@(-15,30)` |

| `rotate-blocked` 抖动 | 构造被围住的局面 → `旋转失败：L01_A（四策略全失败，未提交）` + `[ItemLayer] 抖动 L01_A（转不动）`，幅度 8px / 160ms |

**备注**：`rotateInPlace` 的四策略会 nudge 挪锚点（实测 (0,0)→(0,1)→(1,1)→(1,2)→(2,1)），"原位旋转"实际会把物品挪到相邻位。这是 core 自 M1-0 起的既定行为，**朝向**四次回初态符合 AC06；位置漂移是否要收敛到"严格原位"是**待定项**（见 §待定）。
