## G1-1 手指遮挡 —— ❌ 不过关

**判据**：UI Spec 6 节「长按并拖动物品 → **物品提升、浅阴影、跟手**」；触屏设计「拖动物品时应采用『**手指不遮挡目标格**』的视觉偏移策略，具体偏移按设备和试玩结果调整」。

**现状**：`PreviewLayer` 的 ghost 按手指锚点绘制（`grabOffset` 全程保持，M1-5 定的语义），**没有上浮偏移、没有放大、没有阴影**。真实手指按下时，ghost 就在指尖正下方 → 完全被手挡住，玩家看不到"现在悬在哪一格"。

**证据**：M1-5 起所有拖拽截图/日志均显示 `nodePos=(0,68)`（节点零偏移），ghost 绘制坐标 = 手指锚点换算出的格，无视觉抬升。

**要做的事**（建议 M1-9，与 G1 同批）：

1. 拖起时 ghost **整体上浮** `UI_DRAG_LIFT_PX`（建议 24 设计单位 ≈ 手指半宽的量级，真机再调）；
2. 轻微**放大**（建议 1.05）+ 浅阴影（半透明深色圆角块偏移 2px，与 UI Spec「右下短而淡的结构阴影」一致）；
3. **硬约束**：上浮与放大**只能改画法，不能改判定**——落点仍由手指位置经 `snapToGrid` 算出（M1-5 定的三处取整语义不变）。否则 G1-2「松手落格 = 预览所示格」立刻破功。
   → 实现上：偏移画在 `PreviewLayer` 的 Graphics 路径上（或 `PreviewRoot` 的子节点），**不要**挪 `PreviewRoot` 节点本身（M1-7 踩过：位移 tween 不归位会留下 8px 偏移）。

## G1-2 吸附 —— ✅ 通过

**判据**：「松手落格 = 预览所示格，无一格漂移」。

**读数**（无头预览，多次一致）：ghost 报格与最终 placement 完全一致。

```
[PreviewLayer] ghost L01_A@(0,0) rot=0 → ok
[GameController] 放入 L01_A → (0,0) rot=0
```

四拖通关（A@(1,1) / B@(1,0) / C@(2,1) / D@(0,0) 铺满 3×3）与 M1-6 的 13 连压力用例均未出现漂移；`BoardView` 落点换算式已钉死在 `MEMORY.md`（`pointerRow = round((pageY−183)/114)`）。

## G1-3 旋转手感 —— ✅ 通过

**判据**：「旋转后预览即时更新；`rotate-blocked` 抖动反馈清晰」。

| 子项 | 读数 |
| --- | --- |
| 托盘物品旋转后预览更新 | 点 0 号槽两次 → 缩略图 `60×30`（横）→ `30×60`（竖），且高亮 `selected`。日志：`L01_A@76px(selected) 缩略30×60@(-15,30)` |
| 已放物品原位旋转 | 点已放物品 → `旋转 L01_A → 朝向 1 现位于 (0,1)`，视图同帧重绘（朝向 1→2→3→0，四次回初态 = AC06） |
| `rotate-blocked` 抖动 | 构造被围住的局面 → `旋转失败：L01_A（四策略全失败，未提交）` + `[ItemLayer] 抖动 L01_A（转不动）`，幅度 8px / 160ms |

**备注**：`rotateInPlace` 的四策略会 nudge 挪锚点（实测 (0,0)→(0,1)→(1,1)→(1,2)→(2,1)），"原位旋转"实际会把物品挪到相邻位。这是 core 自 M1-0 起的既定行为，**朝向**四次回初态符合 AC06；位置漂移是否要收敛到"严格原位"是**待定项**（见 §待定）。
