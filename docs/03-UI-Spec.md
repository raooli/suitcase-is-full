## 1. 设计目标和范围

- **核心目标**：一眼看懂「把物品放进行李箱」；拖拽时空间清晰、放下时反馈舒服、过关时有明显成就感。
- **风格**：奶油旅行手账、轻手绘、柔和立体感；视觉服务网格辨识和拖拽交互，不做复杂写实 3D。
- **范围**：首页、核心游戏页、通关状态、关卡选择页；包括常用组件、交互状态和转场。
- **不包含**：人物、剧情、Live2D、商店、排行榜、登录、强制广告、复杂动效。首版以竖屏适配为主。

## 3. 画布、布局与适配

- 基准画布：**390 × 844** 逻辑像素，竖屏。实际游戏建议以 390 作为设计宽度参考，在 Cocos 中按可视区域适配；不是将所有设备强制拉伸至 390×844。
- 安全区：内容水平至少留 **20–28px**；顶部考虑微信环境和刘海/状态区域，底部操作区避免与手势条冲突。
- 结构：顶部关卡信息 约 120px → 行李箱棋盘（视觉中心）→ 待装物品托盘 → 底部操作按钮。
- **棋盘格必须正方形**，横向、纵向统一 cellSize；适配时按可用宽高的较小缩放比例计算，不能分别伸缩 X/Y。
- 棋盘最大列/行数以 GDD 为准；当 6×6 以外尺寸出现时动态计算格子尺寸，保证棋盘完整可见。棋盘与托盘不得重叠。
- **棋盘尺寸需动态计算、不得写死。V1.1 起尺寸集合为：3×3（第 1 关）、4×3（第 2 关）、5×4（第 3–4 关）、5×5（第 5–6 关）、5×6（第 7–8 关）、6×6（第 9–10 关）；第 3 关由 4×4 改为 5×4。格子的 `cellSize` 一律按「可用宽高较小比例」推算，六种尺寸必须全部覆盖，不得仅针对某一尺寸调参。**
- **棋盘与托盘之间必须留出足够的「取出」判定缓冲带**：玩家把物品拖到棋盘外（通常是往下拖回托盘方向）松手即为取出，缓冲带太窄会导致取出与「箱内微移」误判。
- 小屏设备：优先压缩标题、装饰留白和托盘间距，**不能**把可点击按钮缩至不可操作；必要时将托盘改为可横向滚动。**棋盘最小 `cellSize` 建议 ≥ 36px**；6×6 在 320px 窄屏（扣除 20–28px 安全边距后约 264–280px 可用宽）单格约 44px 仍可接受，若低于下限则优先继续压缩托盘/留白而非缩小棋盘，极端机型必要时允许棋盘轻微滚动。
- 大屏设备：限制内容区最大宽度，避免物品和按钮显得过于分散。

### 4.1 Art Style V1.0（已确认）

**风格定位：** 奶油旅行手账、轻手绘、圆润简化、柔和低饱和、轻微立体感。物品首先要清楚表达占格形状，其次才是装饰细节；不追求写实材质或复杂 3D。

**双基准图（后续素材必须同时对齐）：**

| 基准物品 | Figma 节点 | 校准重点 |
|---|---|---|
| `prop_01_A` 手机（1×2 横条） | [打开基准图](https://www.figma.com/design/Wh2Cg8yFw7ph1yUxy1COe4?node-id=15-2) | 小尺寸轮廓、圆角、最小细节密度。**注意：数据是横向 1×2 且不可旋转，必须横着画** |
| `prop_umbrella` 长柄伞（1×5 横条） | [打开基准图](https://www.figma.com/design/Wh2Cg8yFw7ph1yUxy1COe4?node-id=15-23) | 细长轮廓、跨格可读性、装饰性出血。**V1.3 修正：原写 `prop_03_D`，该 itemType 不存在；同款竖向件为 `prop_07_A`（5×1），两件都要出图** |

**绘制约束：**

- 轮廓使用暖棕 `#7A5C4F`，禁止纯黑粗描边；基准输出下描边不超过 **2px@2x**，圆角和转折保持柔和。
- 填色从本规范 Design Tokens 派生，以 `#FFE0E7`、`#BCEAD5`、`#BDE4F7` 等低饱和浅色为主；相邻物品须保持可辨明度差。
- 统一采用**左上柔光、右下短而淡的结构阴影**；只用少量高光表达体积。禁止长投影、外发光、强镜面、高对比厚涂。
- 细节只保留识别物品所需的结构；禁止文字、Logo、品牌和在单格尺寸下不可读的纹理。
- 主体轮廓必须完整落在 `cells` 包围盒内；允许 ≤10% 的伞柄、肩带等装饰性出血，但不得遮挡邻格判定。透明区、阴影和高光均不参与碰撞。
- 四个朝向由 Cocos `Node.angle` 旋转实现，**每件物品只出一个朝向**；不得为不同朝向分别绘制，以免光源漂移。

**资源规格与目录：**

| 交付物 | 规格 | 仓库路径 |
|---|---|---|
| 可编辑源稿 | SVG，图层和路径可继续编辑 | `art/art-source/props/<itemType>_<语义>.svg`（不进包） |
| 游戏贴图 | PNG-24 透明底，@2x；单格 96×96px，画布为包围盒列/行数 × 96px | `assets/resources/sprites/props/<itemType>.png` |
| 风格参考图 | 含背景、网格与说明，仅供 AI/人工评审，不进入游戏 | `art/previews/props/<itemType>_reference.png` |

运行时资源键使用 `itemType`（`spriteKey` 与 `itemType` 63/63 不同，已降级为历史字段，见架构文档 ADR A-11）。禁止纯白底假透明、白边、裁切主体或用参考画板 PNG 充当游戏贴图。

**批量生产与验收：** 先用上述两张基准图校准，单件通过后再继续下一件，不一次性盲目放量。每件须通过：① 缩到 25% 仍能读出占格数；② 与相邻物品有清晰明度差；③ 主体不越出逻辑包围盒；④ 旋转 90° 后风格与光照仍一致；⑤ 透明底、无白边、尺寸和命名正确。尺寸与朝向由 `npm run check:art` 自动校验（不肉眼量）。AI 生成结果必须经过人工精修与商业使用合规确认后才能作为最终素材。

**逐件出图提示词（Style Block / Object Block / Spec Block / Output Block + 63 件清单 + 批次计划）见 [`docs/07-AI-Prompts.md`](./07-AI-Prompts.md) 第 5 节。**

## 5. 界面详细规范

### 5.1 首页

- 标识与主标题为最重要信息；一句副标题说明「收纳/解压」；视觉主角为打开的行李箱和几件物品。
- 主 CTA：「开始收纳」，点击后优先进入用户最新待玩关卡；首次进入第 1 关。
- 首页美术可以略夸张，但**不代表实际棋盘可玩形状**。

### 5.2 游戏页（P0）

- 顶部：返回、当前关卡、关卡副标题、装入进度（`已装入 X / N`）。
- 中部：带箱体边框的正方格棋盘，内部单元格有微弱的交替背景，不依赖颜色作为唯一信息提示。
- 棋盘格是交互判定的唯一依据；物品插画与占用格独立分层，美术允许有限越界但不能遮挡邻近物品的格子判定。
- 下部：未装入物品托盘；支持拖起物品并移动到棋盘，在托盘中展示真实占位轮廓；物品数量多时横向滚动。
- 底部：撤回、旋转、提示；**旋转按钮只有在选中/拖动物品时有效**，否则置灰并提供轻量反馈。
- **首次引导层（对应 PRD F13，P0）：** 第 1 关首次进入展示「拖动物品入箱」的手指示意 + 蒙层高亮（玩家拖动或点击后自动消失），第 3 关首次进入展示「点击旋转按钮」引导；由 `GuideOverlay` 组件实现，仅作用于提示层级、不拦截棋盘核心交互，已学会后本关不再重复弹出。引导出现时棋盘仍可被拖拽。
- 托盘与棋盘之间要留出拖拽过程的通路；浮动预览提升到最高交互层，避免被箱体遮挡。

### 5.3 通关状态

- 触发条件：所有必需物品合法放入，游戏逻辑完成判定后触发。
- 动画建议：最后一件物品回弹（100–180ms）→ 行李箱合盖（250–450ms）→ 轻微星光与「整理完成！」→ 下一关按钮可用。
- 提供「下一关」主按钮与「再来一次」次入口。第 10 关展示阶段完成提示，不能跳转到未实现关卡。
- **星级展示是视觉提案，MVP 不承诺正式星级规则**；如无 GDD 定义的星级计算，应移除星级奖励暗示，改为纯装饰星光。

### 5.4 关卡选择

- 关卡卡片依序呈现：已完成、当前可玩、尚未解锁三种状态。
- 未解锁卡片不可进入；对锁定原因仅提供简短说明。
- 当前关卡应有明显选中态，不能只用颜色表示。

## 6. 核心交互与状态机

| 状态 | 用户行为 | 视觉反馈 | 系统行为 |
|---|---|---|---|
| Idle | 点击托盘物品 | 高亮物品轮廓 | Selected（托盘物品） |
| Selected（托盘或已放物品） | 点击旋转 | 轮廓旋转 90° | 更新朝向并重新检查；托盘物品影响后续落位，已放物品为合法**原位旋转**（提交并入撤回栈），若新朝向在原锚点冲突则不提交非法占位，保持预览并要求重选位置或回退朝向 |
| Selected（已放物品） | 点击棋盘内已放物品 | 高亮其轮廓与当前朝向 | 进入已放物品选中态，可拖动重排或原位旋转 |
| Selected（托盘/已放） | 点击棋盘空白或托盘空白 | 取消高亮 | 回到 Idle，不提交任何操作 |
| Selected / Idle | 长按并拖动物品 | 物品提升、浅阴影、跟手 | Dragging |
| Dragging | 经过合法棋盘位置 | 绿色占位投影 | 仅预览，不提交 |
| Dragging | 经过非法位置 | 红色占位投影和轻微阻尼 | 禁止放置 |
| Dragging | 抬手且合法（棋盘内） | 吸附到格子、轻弹音效 | Committed，保存历史快照 |
| Dragging | 抬手且非法（棋盘内） | 回弹到原位 | 恢复前态，不扣次数 |
| **Dragging（已放物品）** | **拖到棋盘外** | **预览切换为「取出」态：物品半透明 + 托盘目标位高亮；禁止显示红色非法** | **Released-outside 判定** |
| **Dragging（已放物品）** | **在棋盘外抬手** | **飞回托盘原位置的短动画** | **取出：释放占位，回托盘原 `trayOrder` 位，保留朝向，入撤回栈** |
| **Dragging（托盘物品）** | **在棋盘外抬手** | **留在托盘，无动画** | **无操作，不入撤回栈** |
| **Dragging（任意）** | **被系统中断（`touchCancel` / 来电 / 下拉通知）** | **取消拖拽动画，物品回到操作前位置** | **恢复前态，不视为取出，不入撤回栈** |
| Committed | 再次拖动已放物品 | 从原位置提升 | 允许重新调整（同 Selected（已放物品）路径） |
| 任意可交互态 | 点击撤回 | 轻微逆向位移动画 | 回滚到最近一次有效提交前的**完整快照（位置与朝向）**；已放物品撤回后回到操作前位置且**保留当时朝向**，不重置为 `cells` 初始朝向 |
| 任意可交互态 | 点击工具栏「重置」 | 弹出 `ConfirmDialog` 二次确认后恢复 | 清空本关布局，恢复物品初始朝向 / 初始托盘顺序 / 空棋盘，保留障碍与关卡解锁 |
| Committed | 最后一件合法放入 | 合盖、庆祝 | Success，保存进度 |

**关键约束：** MVP 不限时、不限操作次数，也没有死亡/失败复活流程。禁止在 UI 中预设「看广告复活」作为首版默认交互。提示功能可以展示入口，但未实现时不得伪装成可用；默认优先免费提供若干次测试提示。

### 触屏设计

- 拖动物品时应采用「手指不遮挡目标格」的视觉偏移策略，具体偏移按设备和试玩结果调整。
- 旋转采用固定 90°，可在已选中时点击按钮；拖动中旋转是否启用属于技术验证项，若实现复杂，MVP 允许只在放置前/选中后旋转。
- **取出手势（V1.1）**：把已放置物品拖离棋盘包围盒（外扩半格）后松手即取出。**拖拽过程中，只要物品中心越过棋盘外边界，预览就必须从「非法红」切换成「取出态」**——否则玩家会以为松手会失败而缩回去，这条规则就形同不存在。
- **切勿把 `touchCancel` 当成取出处理。** 系统中断与主动拖出在事件类型上不同，混淆会导致来电后物品凭空回到托盘。
- 缩放动画不可影响逻辑占位、碰撞检测或网格吸附。
- 非法放置时不显示强制失败弹窗，而是回弹并解释原因（如「这里放不下」）。

| ItemSprite | 待选、选中、拖动、已放 | 透明 PNG 或 SpriteAtlas |
| SuitcaseFrame | 空状态、游戏中、合盖 | 分层美术，预留内棋盘缩放 |
| LevelTile | 已完成、当前、锁定 | 统一尺寸和圆角 |
| SuccessOverlay | 成功入场、稳定展示 | 半透明遮罩，禁止背景误触 |
| **HintToast（V1.1）** | **「装不下」面积提示** | **非阻断轻提示条，约 2s 自动淡出；不遮挡棋盘、不拦截触摸、不含按钮** |
| **TraySlot（V1.1）** | **空位 / 取出目标位高亮** | **取出拖拽时高亮目标空位，让玩家能预期落点** |
| **GuideOverlay（V1.2）** | **首次引导：手指示意 + 蒙层高亮** | **第 1 / 3 关首次进入触发；仅提示层级、不拦截棋盘拖拽；本关已学会后不再弹出** |

**资源命名建议**：`ui/home-hero`、`ui/suitcase-open`、`ui/suitcase-closed`、`items/<item-id>`、`icons/tool-undo`、`icons/tool-rotate`、`icons/tool-hint`。优先复用相同图集、背景切片和程序化网格绘制。插画资产应记录来源与商业使用授权，不直接把 Figma 中的色块占位当成终稿素材。

## 8. 动画与音效

- 拖拽抬起：约 80–120ms，略微放大或加投影。
- 放置吸附：约 120–180ms，轻弹缓动；失败回弹 150–250ms。
- 旋转：约 120–180ms；逻辑朝向瞬时更新，视觉平滑过渡。
- 成功合箱：250–450ms + 轻微星光（减弱频闪）。
- 音效：选中轻点声、合法放置咔哒声、非法放置柔和提示声、成功扣锁声；默认尊重设备静音配置，可关闭音效。
- 动画持续时间为设计建议，需在真机上测试 30/60 FPS 下的跟手感与响应。

## 9. Cocos Creator 落地指导

- 以 Cocos UI 系统组织 `Canvas` → `SafeAreaRoot` → `Header` / `Board` / `Tray` / `Toolbar` / `Overlay`。
- 棋盘逻辑以 GDD 坐标系为准；视觉坐标转换在单一 `BoardView` 完成，避免多处计算带来取整误差。
- `GridRenderer`、`ItemView`、`DragController`、`Toast`、`SuccessOverlay` 分离；所有状态更新由游戏逻辑层发出事件。
- 关卡数量/物品形状不能从 Figma 截图推断；必须读取已验证的关卡 JSON。
- 建议先用占位色块完成整套拖拽和碰撞，再替换美术，以降低调试成本。
- Figma 负责视觉规范和布局，不等价于可直接运行的 Cocos 场景；AI 生成代码仍需在编辑器中验证。

## 10. 可用性、性能与质量验收

1. 390×844 基准尺寸上四页内容无裁切、主要操作按钮清晰可见。
2. 320px 左右窄屏上棋盘完整显示；工具栏和托盘不发生触控重叠。
3. 拖拽预览与最终合法位置一致；非法放置不改变已提交棋盘数据。
4. 已放物品可再次拖动，撤回/重置不会丢失合法状态。
5. 旋转后占位轮廓与逻辑形状同步，不能出现图像转了而碰撞格未转。
6. 物品颜色相近时仍可通过轮廓和形状辨认；障碍格具有独立的形状标识。
7. 动效可跳过或以低配置模式简化，不影响核心操作。
8. 关卡数据可解性以 GDD 校验器为准；Figma 仅验视觉，不承担关卡验证。
9. 首版离线正常运行；无网络时不阻断首页、核心玩法和本地存档。
10. 待接入激励广告前，提示入口提供可用的免费提示或明确禁用，不出现空按钮。
11. **（V1.1）取出交互可预期**：拖到棋盘外时预览为「取出态」而非红色非法；松手后物品回到托盘原位并保留朝向；不出现物品丢失或悬空。
12. **（V1.1）系统中断可恢复**：`touchCancel` 后物品回到操作前位置，不误触发取出。
13. **（V1.1）「装不下」提示不阻断**：提示出现时棋盘仍可操作；提示为纯信息，不含确认按钮，不判失败。
14. **（V1.2）首次引导可跳过**：第 1 / 3 关引导出现时棋盘核心交互仍可用，玩家拖动或点击后即消失，本关不重复弹出。
15. **（V1.2）文字对比度达标**：`color.text.secondary`、`color.brown` 在 `#FFF8EE` 背景上 ≥ 4.5:1（WCAG AA，14px 及以上正文）；合法/非法预览仍依赖轮廓与形状，不依赖颜色单通道。
