## 1. 分层与依赖规则

### 1.1 分层图（依赖只能向下，不能向上或跨层）

```
┌─────────────────────────────────────────────────┐
│  L3  view/            允许 import 'cc'          │  Cocos 组件、场景、动画
│      platform/        允许 import 'cc' + wx API │  存档/音频/震动/广告
├─────────────────────────────────────────────────┤
│  L2  core/session     GameSession（状态机）      │  零 cc
│      core/rules       canPlace / applyPlacement  │  零 cc
│      core/solver      求解与死局快检             │  零 cc
├─────────────────────────────────────────────────┤
│  L1  core/model       类型与 LevelSpec 校验      │  零 cc
│      core/geometry    形状、坐标                │  零 cc
│      core/config      全部可调参数               │  零 cc
└─────────────────────────────────────────────────┘
          ↑  tools/ 与 test/ 只依赖 L1+L2（Node 侧，不进包）
```

### 1.2 依赖规则表（**硬性**）

| # | 规则 | 违反的典型症状 |
| --- | --- | --- |
| R-A1 | **`core/**` 任何文件不得出现 `import ... from 'cc'`** | 单测全挂、Node 侧跑不了、迁移 COCOS 4 时 core 要重写 |
| R-A2 | **依赖只能向下**：`view → session → rules → model/geometry` | 逻辑散在视图里，改一处崩三处 |
| R-A3 | **`view/` 与 `tools/` 只从 `core/index.ts` 导入**，不得深引内部路径（`core/rules/board` 等） | core 内部重构会波及调用方 |
| R-A4 | **`platform/` 是唯一能碰 `wx` / `localStorage` 的地方** | 微信 API 散落，Web 预览直接白屏 |
| R-A5 | **`core` 不得依赖 `view` / `platform`**（含类型反向引用） | 循环依赖，tsc 与 Cocos 都可能编译失败 |
| R-A6 | **坐标转换只在 `BoardView.gridToLocal / localToGrid / shapeMetrics`**；其他文件禁止出现 `cellSize` / `cellPx` 算术 | 拖拽偏移 bug 的经典来源 |
| R-A7 | **`assets/data/` 只读**，运行时不写；关卡真相源是 GDD JSON + `tools` 产物 | 两份真相，改了不生效 |
| R-A8 | **运行时贴图必须位于 `assets/resources/` 下**，文件名严格 = `itemType` | `resources.load()` 拿不到，只能做 63 项手工映射 |
| R-A9 | **`assets/` 下只放运行时资源**：`art-source/`（SVG）与 `previews/` 必须留在仓库根的 `art/` | Cocos 会扫描并生成 `.meta`，SVG 非受支持类型可能导入报错，评审图可能混入包体 |

> **豁免：** `test/**` 允许深引 `core` 内部路径（单测就是要打进内部单元）。豁免显式写在 `tools/check-arch.ts` 里，不藏在配置中。

## 3. 命名与文件规范

| 对象 | 规范 | 例 |
| --- | --- | --- |
| 目录 | 小写单词；集合语义用单数（`view`、`rules`、`solver`） | `core/session/` |
| 文件（导出类/组件） | **PascalCase**，且与导出的类名**完全一致**（Cocos 挂载依赖这个） | `GameSession.ts`、`ItemView.ts` |
| 文件（纯函数集合） | **camelCase** | `coords.ts`、`packer.ts`、`placement.ts` |
| 类 / 接口 / 类型 | PascalCase，**不加 `I` 前缀** | `LevelSpec`、`DragPreview` |
| 常量 | UPPER_SNAKE，且**必须集中在 `config.ts`** | `OWNER_EMPTY` |
| 事件 `type` | kebab-case 字符串字面量 | `'placement-committed'` |
| 运行时贴图 | `assets/resources/sprites/props/<itemType>.png`，**严格等于 itemType，不加语义后缀** | `prop_01_A.png` |
| 矢量源 / 评审图 | `art/art-source/props/<itemType>_<语义>.svg`、`art/previews/props/<itemType>_reference.png`，**允许语义后缀**（人工可读） | `prop_01_A_phone.svg` |
| 场景 | PascalCase | `Game.scene` |

> **资源键的裁决：以 `itemType` 为唯一资源键。** 关卡数据里的 `spriteKey`（形如 `placeholder/01/A`）与 `itemType` **63/63 全不相同**，两者并存会导致双映射。`spriteKey` 降级为历史字段，**不再作为资源路径**。运行时按 `resources.load('sprites/props/' + itemType + '/spriteFrame')` 加载，零映射表。

**两条硬约束：**
- **禁止魔法数字。** 任何阈值、尺寸、时长、容差都进 `core/config.ts`，view 侧从 `index.ts` 读。TDD 第 3 节已列 P-01～P-07。
- **组件文件必须与类名同名。** Cocos 靠文件名识别组件，不一致会导致挂不上脚本。

## 4. 模块职责与接口契约

### 4.1 core 对外契约（`view` 能用的全部）

| 成员 | 类型 | 用途 |
| --- | --- | --- |
| `dispatch(intent: Intent): SessionResult` | 方法 | **view → core 的唯一入口**（TDD 7.2） |
| `getState(): LevelState` | 方法 | 视图渲染的唯一数据来源 |
| `getPhase(): GamePhase` | 方法 | 阶段判定（playing / cleared …） |
| `getPreview(): DragPreview \| null` | 方法 | 拖拽预览三态 |
| `canUndo` / `moves` | 只读属性 | 工具栏状态 |
| `completeWinAnimation(): void` | 方法 | 通关动画结束后由 view 回调（TDD 3 节） |
| `debugSnapshot()` | 方法 | 调试用，禁止进入生产逻辑 |

> 完整导出清单见 `assets/core/index.ts`（**这是契约的唯一真相源**，本文档不复制）。

### 4.2 事件流（单向，不可反向）

```
触摸 → DragController → Intent → GameSession.dispatch()
                                      ↓ SessionResult { state, phase, events }
                                 GameController 订阅 → BoardView / TrayView / ItemView / AudioAdapter
```

**事件清单见 TDD 8.2（10 种）。本文只强调三条铁律（TDD 8.3）：**

1. **动画不持有状态** —— B 位置来自已提交的 `state`；动画中被打断就 `tween.stop()` 重画，绝不"等动画播完再提交"。
2. **坐标转换只有一个地方** —— `BoardView`。
3. **view 不缓存逻辑** —— `ItemView` 不存"我是否被放置"，每次从 `state` 读。

### 4.3 视图层组件职责（M1 实现时按此分工，避免重叠）

| 组件 | 只负责 | 明确不负责 |
| --- | --- | --- |
| `DragController` | 触摸 → `Intent`（含 grabOffset） | 不判定合法性 |
| `BoardView` | 网格渲染 + 坐标转换 + 形状像素出口（`shapeMetrics`，R-A6 唯一出口） | 不做碰撞 |
| `PreviewLayer` | 三态视觉（合法/非法/取出） | 不决定是否可放 |
| `ItemView` | 占位外观（色块/明度阶梯，M1-2 → 真图 M4-5）+ 位置/旋转/朝向的 tween | 不存任何逻辑状态；不做坐标转换（像素全由 `BoardView` 给）；不加载资源 |
| `GameController` | 订阅事件并分发 | 不写玩法规则 |

## 5. 代码规范

| 项 | 规定 |
| --- | --- |
| 语言 | TypeScript，`strict: true`（现状已满足，不得降级） |
| 模块 | ESM；`core` 内禁止循环 import |
| import 顺序 | `cc` / 三方 → `core/index` → 相对路径；各组之间空行 |
| 纯函数优先 | `core` 内不写可变全局；状态只由 `GameSession` 持有 |
| 集合复制 | **禁止展开语法 `[...x]`，一律 `Array.from(x)`**。Cocos 3.8.8 构建的转译是 loose 模式，`[...set]` 会被降级成 `[].concat(set)` → `[set]`（Set 被当作单个元素），而 Node/Vitest 里展开是规范的——症状是「单测全绿、引擎里数据莫名出错」。`for...of` 遍历不受影响（转译用的是迭代器 helper）。由 R-A10 机械拦截 |
| 不可变 | 撤回栈用快照（TDD 7.3）；禁止"反向操作"式撤回 |
| 注释 | 写**为什么**，不写**做什么**；`core/index.ts` 的注释风格即为范本 |
| 错误处理 | `core` 抛 `LevelDataError`（已有）；view 侧一律降级为 UI 提示，不吞异常 |
| 日志 | 仅 `debugSnapshot()` 与 dev 环境；构建前确保无 `console.log` 残留 |
| 提交 | 每次 commit 追加 `CHANGELOG.md`；`npm run check` 不过不提交 |

## 7. 资源加载策略与内存预算

### 7.1 加载方式

```ts
// ItemView / 资源服务（view 层）
const sp = await resources.load(`sprites/props/${itemType}/spriteFrame`, SpriteFrame);
```

- **不用 63 项手工映射**：文件名 = `itemType`，路径可拼接，零维护。
- 关卡加载时**预载本关 ≤9 件**，`resources.release` 在切关时释放上一关。
- 占位阶段用程序化色块（同尺寸），替换真图时布局不变。

### 7.2 内存预算（**决定 @2x 还是 @4x**）

| 倍率 | 单格 | 63 张纹理解压内存（估） | 结论 |
| --- | --- | --- | --- |
| @2x（**规格**） | 96 px | 约 **5～6 MB** | ✅ 采用 |
| @4x（当前基准图） | 192 px | 约 **22 MB** | ❌ 小游戏不可接受 |

> 估算口径：纹理解压后 = 宽 × 高 × 4 字节，取 63 张平均包围盒约 2.5×2 格。**实际值以 M3 真机 Profiler 为准**（U-03）。

### 7.3 图集与 resources 的兼容（待验证，V-06）

图集能显著减少 draw call，但 `resources/` 下的散图被合图后 `resources.load` 原路径是否仍命中，**需 M1 实测**。

- 可行 → 保留 `atlas/items` 合图 + 原路径加载。
- 不可行 → 退化为"按图集名 + spriteFrame 名加载"，或放弃合图（63 个小图，draw call 压力可接受）。
