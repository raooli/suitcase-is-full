## M4-4 非物品资源齐活（提交 0e97260）

**交付**：UI 插画 3 张 + 音效 4 个 WAV。素材仍 25/63（物品侧未动）。

- **`ui/home-hero` 560×400**：首页英雄图（正视开口箱 + 长裙/化妆包/围巾）。
- **`ui/suitcase-open` 780×780**：棋盘箱体，**俯视开口**、正方形内衬。
- **`ui/suitcase-closed` 780×780**：通关合盖终态，**与 open 同轮廓同画布**（合盖动画才能交叉淡出而不跳位）。
- **音效** `select/place-ok/place-fail/success` = 70/110/220/340ms，44100Hz·16bit·mono。

**三个关键判断**：

1. **俯视是约束不是偏好**。棋盘是正方形（L10 6×6 = 342×342），正视「盖子竖起」的插图没有能承载正方形网格的平面。v1 就是那么出的：内衬 1.68:1、底色暖米 `rgb(238,229,211)` 与箱体同色系 → 抠底只挖掉 9.3%、覆盖率 89.8%，**整张废弃**。v2 俯视对了但内衬还是扁的 → 也废。v3 把「SQUARE，宽=高，占 78%」写死才成。
2. **其余 5 类组件定案保持程序化**（按钮/图标/格子/关卡卡/浮层）。判定口径写进 docs/03 §7.2：**「一件东西的画像」→ 出图；「会变形的容器/状态机」→ 程序化**。理由不是省事——三态按钮要 3 张且改文案要重出图；棋盘尺寸随关卡变（3×3~6×6）贴图九宫格会糊；引导层的高亮洞必须「真的透明」。
3. **音效电平口径**：WAV 归一化 **0.70 峰值**、**不烘焙 `SFX_MASTER_GAIN`(0.22)**——那是合成后端的余量常量，该由播放器 volume 承担。M4-5b 设 volume=0.22 → 有效 0.154 与今天同听感；**若 volume=1 直放会响 6 倍**。首尾过零（≤2e-4）无爆音。

**顺带做了索引色 PNG（大收益，也是踩坑处）**：
- `art-batch-proc.mjs` 新增 `encodeIndexedPNG`（colorType 3 + PLTE + tRNS）与 `optimize <文件|目录>`（对已交付 PNG 重编码，**不改像素**）。超 256 色自动回落真彩，不静默丢色；`fit` 想强制真彩加 `--rgba`。
- 实测：props 25 张 225.4→**152.8KB（省 32%）**（22 张转成，prop_07_A/scarf/umbrella 超色保持真彩）；UI 三张 545.7→**208.3KB**（closed 省 65%）。
- **坑（必须记住）**：索引色每个调色板项只有一个 alpha。图省事让所有 α=0 共用一个 `(0,0,0,0)` 槽位 → 透明区 RGB 全变黑 → **双线性采样会把实色和黑混合，物体外缘描一圈黑边**。正确做法=透明像素 RGB **吸附到最近实色**（颜色外扩/bleed）。实测 `prop_05_A` 边缘透明像素近黑占比 0%、均值 `rgb(147,73,27)` 正是描边棕，比转换前的底色晕更干净。
- `check-art.ts` 解码器已支持 colorType 3（否则索引色图会被判「非 RGBA」而全部阻塞）。

**`check:art` 新增 UI 段**：`UI_SPECS` 契约表（name + w + h + use）逐张校验尺寸与透明底，`sprites/ui/` 孤儿检测。**尺寸是契约**——M4-5b 按这些像素摆位，改尺寸要同步改表和 docs/03 §7.1。

**验收**：`npm run check` 340/340；`check:art` 25/63 + UI 3/3；微信包重建 **121 文件 2,497,080 B = 2.38MB**（28 PNG + 4 WAV 都在包内）；`preview:game` 零 Console 错误、4 件「真图已载入」——**顺带证明索引色 PNG 引擎侧可读**。

**归档**：`art/art-source/ui/ai/<name>.prompt.md`（提示词+参数+后处理命令+版本踩坑）+ `art/previews/ui/<name>_reference.jpg`（512 长边，共 97KB）。规则与 props 一致（AI 件无 SVG 源）。
