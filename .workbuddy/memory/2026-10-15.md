## 分支保护声明式配置 + 应用脚本（本轮）

- **关键事实（先讲清）**：branch protection 存在 **GitHub 服务端**，不在 git 仓库里，**git push 推不上去**；`.github/*.yml`（Actions/PR 模板/CODEOWNERS）都管不到它。用户问"能否用项目文件实现"——不能直接实现，但可以把规则写成**声明文件**再用脚本调 API 应用，这才是正确形态。
- **新增**：`.github/branch-protection.json`（预设 safe/strict/ci + branches 映射）、`.github/BRANCH-PROTECTION.md`（说明）、`tools/protect-branch.mjs`（应用器，默认 dry-run）、`package.json` 加 `protect:branch`。三档设计：safe=禁强推/禁删除/管理员受约束但**不要求 PR**（单人项目默认，否则把自己锁死）；strict=PR+1 approve；ci=另加状态检查（**本项目暂无 Actions，暂不可用**，context 名必须与 workflow job 名一致否则 PR 永久卡住）。
- **dry-run 立刻抓到一处安全关键 bug**：GitHub protection 载荷里 `allow_force_pushes.enabled` 的语义是「是否**允许**强推」而非「是否启用该保护」。按后者理解会写出 `allowForcePushes:false → enabled:true` 的**反向**载荷——字段齐全、HTTP 200、GitHub 不警告，但守卫全被关掉。属典型**静默失效**。
- **为此加了载荷自检** `selfCheckPayload`：配置写 false 则载荷 enabled 必须 false，否则中止 exit 3。已做**负向验证**（注入方向错误 → exit 3；恢复 → exit 0），确认自检不是装饰。
- **另一个坑**：branch protection API **只接受精确分支名，不支持通配符**（`release/*` 会 404）。通配符要用 Repository Rulesets。脚本对含 `*` 的模式明确跳过并提示改用 Rulesets，而不是让 404 被误读成"规则没生效"。
- token 只从 env 读（GITHUB_TOKEN/GH_TOKEN），永不落文件/日志；`--apply` 前打印现状vs期望 diff 并要确认；幂等（无差异报"已是目标状态"exit 0）。
- **注意**：本机**未安装 gh CLI**，脚本改用 `curl` 调 REST API（零依赖，与 preview-check.mjs 风格一致）。
